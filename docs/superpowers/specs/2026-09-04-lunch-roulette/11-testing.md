# 11. 테스트

[← 인덱스](README.md)

시간을 다루는 함수는 현재 시각을 인자로 받는다. 테스트가 실제 시계에 의존하지 않기 위해서다. [03-architecture.md](03-architecture.md)

## 계층 1. 순수 함수 단위 테스트 (가장 촘촘하게)

| 대상 | 반드시 포함할 케이스 |
|---|---|
| rules/slot | 10:59 없음, 11:00 lunch, 14:59 lunch, 15:00 없음, 17:00 dinner, 20:59 dinner, 21:00 없음, 다음 슬롯 시각(21:30 → 다음 날 11:00) |
| rules/hours | hours null 제외, 휴무일, open 정각 포함, close 정각 제외, 브레이크 시작 정각 제외, 브레이크 끝 정각 포함, 자정 넘김(어제 17:00~02:00일 때 오늘 01:30 영업 중), 24시간 영업 |
| Google 응답 → hours 변환 | 구간 1개, 구간 2개(브레이크 생성), 구간 3개(첫 공백만 브레이크), 요일 누락(휴무 처리), 영업시간 없음(null), 자정 넘김 구간 |
| rules/level | 0→1, 1→2, 2→2, 3→3, 7→4, 14→4, 15→5, 100→5, 다음 레벨까지 남은 횟수, 5레벨은 표시 없음 |
| 후보 추첨 | 풀 3개면 그 3개, 풀 10개면 서로 다른 3개, 풀 2개면 거절 |

## 계층 2. 서버 액션 통합 테스트

로컬 Supabase에 대해 실행한다. Google API는 고정 응답으로 대체한다.

- 돌리기 → 다시 돌리기 → 확정 정상 흐름. 확정 후 경험치 1, 레벨 2.
- 같은 슬롯에 돌리기 두 번 → 같은 세션 반환.
- 다시 돌리기 두 번 → 두 번째는 REROLL_ALREADY_USED.
- 확정 두 번 → 두 번째는 SESSION_NOT_OPEN, 경험치는 1 그대로.
- 후보 밖 식당 확정 → NOT_A_CANDIDATE.
- 다른 사용자의 장소로 돌리기 → PLACE_FORBIDDEN.
- 다른 사용자의 세션 조회 → RLS로 0건.
- 장소 생성: 지오코딩 실패 시 아무것도 저장 안 됨. override 식당의 hours 유지. 0건이면 장소만 저장.
- 슬롯 끝 이후 open 세션 → 기록에 없음, 경험치 0.

## 계층 3. 화면 테스트

- 홈의 네 가지 상태(슬롯 밖, 세션 없음, open, confirmed)가 올바른 버튼과 문구를 보여 주는지만 확인한다.
- 애니메이션은 테스트하지 않는다.

## 수동 확인 (배포 후)

- 실제 Google 로그인 1회.
- 실제 장소 생성 1건과 식당 수, 영업시간 있는 식당 수 확인.
- Google Cloud 콘솔에서 할당량 제한과 예산 알림이 걸려 있는지 확인. [09-external-api.md](09-external-api.md)
