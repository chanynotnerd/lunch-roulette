# 05. 규칙

[← 인덱스](README.md)

모든 규칙은 서버에서 Asia/Seoul 기준 현재 시각으로 판단한다. [03-architecture.md](03-architecture.md)

## 슬롯

| 슬롯 | 시작(포함) | 끝(미포함) |
|---|---|---|
| lunch | 11:00 | 15:00 |
| dinner | 17:00 | 21:00 |

- 그 외 시각은 슬롯 없음. 돌리기를 거절하고 다음 슬롯 시작 시각을 안내한다.
- 21:00 이후의 다음 슬롯은 다음 날 11:00이다.
- slot_date는 현재 시각의 Asia/Seoul 날짜다.

## 영업 중 판정

식당이 현재 시각에 영업 중이려면 아래를 모두 만족해야 한다.

1. hours가 null이 아니다. (null이면 무조건 제외. D14)
2. 오늘 요일 항목이 closed가 아니다.
3. open ≤ 현재 시각 < close.
4. break가 있으면 break.start ≤ 현재 시각 < break.end 가 아니다.

자정 넘김: 어제 요일 항목의 close가 open보다 이르고 현재 시각 < 어제의 close 이면,
어제 영업의 연장으로 보아 영업 중으로 판정한다. 이 경우 어제의 break는 보지 않는다.
자정 넘김 영업의 break는 open~24:00 안에만 둘 수 있으며, 자정 이후의 break는 표현하지 않는다(보정 파일 검증에서 거부).

경계값: 시각 비교는 분 단위이며 시작은 포함, 끝은 미포함이다.

## 세션 상태

| 상태 | 뜻 | 허용 동작 |
|---|---|---|
| (없음) | 오늘 이 슬롯에 세션이 없음 | 돌리기 |
| open | 후보 3개가 있고 미확정 | 다시 돌리기(미사용 시), 확정 |
| confirmed | 확정 완료 | 없음. 결과 표시만 |
| expired(파생) | open인데 슬롯 종료 시각이 지남 | 없음. 기록과 경험치에 반영 안 함 |

expired는 저장하지 않고 조회 시 "status = open 이고 현재 시각 ≥ 슬롯 끝"으로 판정한다.

## 후보 추첨

- 후보 풀 = 장소에 연결된 식당 중 영업 중인 식당.
- 후보 풀이 3개 미만이면 세션을 만들지 않고 거절한다. 억지로 채우지 않는다.
- 후보 풀에서 서로 다른 3개를 균등 확률로 뽑는다. 레벨은 확률에 영향을 주지 않는다. (D9)
- 다시 돌리기는 같은 규칙으로 3개를 새로 뽑는다. 이전 후보와 겹쳐도 된다.

## 다시 돌리기

- 세션이 open이고 reroll_used가 false일 때만 허용. 성공 시 reroll_used를 true로 바꾼다.

## 확정

- 세션이 open이고, 고른 식당이 candidate_ids 안에 있을 때만 허용.
- 갱신 쿼리에 "status = open" 조건을 넣어 두 번 눌러도 한 번만 반영한다.

## 레벨 테이블

| 레벨 | 이름 | 필요 누적 경험치 |
|---|---|---|
| 1 | 처음 | 0 |
| 2 | 익숙 | 1 |
| 3 | 단골 | 3 |
| 4 | 찐단골 | 7 |
| 5 | 집밥 | 15 이상 |

- 경험치 = 그 식당을 확정한 횟수(사용자별). [04-data-model.md](04-data-model.md)
- 레벨 = 필요 경험치가 현재 경험치 이하인 가장 높은 단계. 5가 최고이며 그 이후 경험치는 계속 쌓이지만 레벨은 오르지 않는다.
- "다음 레벨까지 N회" = 다음 단계의 필요 경험치 − 현재 경험치. 5레벨이면 표시하지 않는다.
- 테이블 값은 코드의 설정 파일 한 곳에만 둔다.
