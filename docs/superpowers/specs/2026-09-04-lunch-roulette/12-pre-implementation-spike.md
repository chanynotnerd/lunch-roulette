# 12. 구현 전 검증 단계 (데이터 품질 스파이크)

[← 인덱스](README.md)

가장 큰 불확실성은 Google의 국내 식당 영업시간 커버리지다. (D16)
구현 계획의 0번 작업으로 아래 스파이크를 수행하고, 결과에 따라 시드 소스를 결정한다.

## 질문

주인님이 실제로 쓸 장소 하나를 기준으로, 반경 500m 안 식당 중
영업시간이 있는 비율과 브레이크타임이 있는 비율은 얼마인가?

## 방법

1. 주인님이 장소 하나(이름, 주소)를 지정한다.
2. Geocoding 1회, Text Search 최대 3회를 호출한다. API 비용은 무료 한도 안이다.
3. 결과를 아래 표로 정리한다.

| 항목 | 값 |
|---|---|
| 검색된 식당 수 | |
| 영업시간이 있는 식당 수와 비율 | |
| 그중 브레이크타임이 있는 식당 수 | |
| 점심 슬롯(12:00 기준) 영업 중으로 판정되는 식당 수 | |
| 저녁 슬롯(18:00 기준) 영업 중으로 판정되는 식당 수 | |

4. 영업시간이 없는 식당 이름을 목록으로 남긴다. 보정 파일의 첫 조사 대상이다.

## 판단 기준

| 결과 | 결정 |
|---|---|
| 영업시간 있는 비율 50% 이상 | Google Text Search로 진행. 보정 파일로 브레이크타임을 메운다 |
| 50% 미만 | 카카오 로컬 API(무료, 결제 등록 불필요)로 식당 목록을 받고, 영업시간은 전부 보정 파일로 채운다. 09-external-api.md와 10-seed-and-overrides.md를 고친다 |

어느 쪽이든 places/search 모듈만 바뀌고 나머지 설계는 그대로다. [03-architecture.md](03-architecture.md)

## 산출물

- 이 파일의 표를 채운다.
- 스파이크에서 만든 코드는 버린다. 단, Google 응답 → hours 변환 로직은 검증된 뒤 본 구현에 옮길 수 있다.
