# 14. 유저플로우 해피케이스

[← 인덱스](README.md)

사용자가 아무 문제 없이 앱을 처음 쓰기 시작해 식사 한 끼를 확정하고 기록으로 남기기까지의 흐름이다.
오류와 예외 분기는 다루지 않는다. 그것은 [06-flows.md](06-flows.md)와 [08-errors.md](08-errors.md)에 있다.

이 파일의 Mermaid 다이어그램이 원본이다. FigJam 보드는 여기서 생성한 결과물이다.
흐름을 바꿀 때는 이 파일을 먼저 고치고 FigJam을 다시 생성한다. 갱신 방법은 맨 아래에 있다.

FigJam 보드: https://www.figma.com/board/TYKrI6JL3kwlVwbXDZyTXL (2026-09-04 Figma MCP `generate_diagram`으로 생성. 최신본은 "가로, 섹션, 라벨 줄바꿈" 플로우차트, 상태 전이 다이어그램, 범례(S·F 정의). 그 전 버전(세로, 가로 라벨 한 줄)은 보드에서 삭제 대상)

## 등장 요소

| 종류 | 번호 | 이름 | 한 줄 설명 | 정의 문서 |
|---|---|---|---|---|
| 화면 | S1 | 로그인 | Google 로그인 버튼 하나. 로그인 상태면 홈으로 자동 이동 | [07-screens.md](07-screens.md) |
| 화면 | S2 | 홈(룰렛) | 장소 드롭다운, 슬롯 상태 문구, 룰렛 영역. 세션 상태(슬롯 밖/세션 없음/open/confirmed)에 따라 표시가 바뀜 | 07 |
| 화면 | S3 | 장소 관리 | 내 장소 목록, 장소 추가 폼, 장소 삭제. 장소를 누르면 연결된 식당 목록과 도장 5칸 | 07 |
| 화면 | S4 | 기록 | confirmed 세션을 날짜 내림차순으로. 날짜, 슬롯, 장소, 식당, 확정 당시 레벨 | 07 |
| 흐름 | F1 | 로그인 | Google 인증 후 장소가 없으면 장소 관리로, 있으면 홈으로 | [06-flows.md](06-flows.md) |
| 흐름 | F2 | 장소 생성 | 주소를 좌표로 바꾸고 반경 안 식당을 최대 60곳 수집해 저장 | 06 |
| 흐름 | F4 | 돌리기 | 슬롯 판정 후 영업 중 식당에서 3곳 추첨, open 세션 저장(슬롯당 1개) | 06 |
| 흐름 | F5 | 다시 돌리기 (선택) | open 세션에서 1회만 후보 3곳 교체 | 06 |
| 흐름 | F6 | 확정 | 후보 중 1곳 선택, 세션 confirmed, 경험치·레벨·레벨업 여부 응답 | 06 |
| 흐름 | F8 | 기록과 레벨 조회 | confirmed 세션 목록과 식당별 도장 5칸. 확정 당시 레벨은 이전 확정 횟수 + 1 | 06 |

레벨은 확정 횟수 기준으로 Lv1 처음 → Lv2 익숙 → Lv3 단골 → Lv4 찐단골 → Lv5 집밥이다. [05-rules.md](05-rules.md)

F3(장소 삭제)과 F7(만료)은 해피케이스에 나오지 않는다.

## 시나리오

첫 사용자가 점심시간에 앱을 열어 회사 근처 식당 하나를 확정한다.

1. 앱을 연다. 로그인 전이라 S1 로그인 화면이 보인다.
2. "Google로 로그인"을 누르고 Google 계정을 고른다. (F1)
3. 로그인 후 S2 홈이 열리는데 장소가 없어 "장소를 먼저 등록해 주세요"와 "장소 관리로 가기" 링크만 보인다. 링크를 눌러 S3 장소 관리로 간다. 이름 "회사", 주소, 반경 500m(기본값)를 넣고 "추가"를 누른다.
4. 서버가 주소를 좌표로 바꾸고 반경 안 식당을 수집한다. "장소를 추가했습니다. 식당 N곳을 찾았습니다"가 보인다. (F2)
5. 하단 탭 "홈"으로 간다. 장소 드롭다운에 "회사"가 선택돼 있고 "오늘 점심" 아래 "돌리기" 버튼이 활성이다. (S2)
6. "돌리기"를 누른다. 서버가 영업 중인 식당에서 3곳을 뽑아 세션을 연다. 룰렛 애니메이션이 1.5~2초 돌고 후보 카드 3장이 나온다. (F4)
7. (선택) 마음에 안 들면 "다시 돌리기"를 한 번 누른다. 후보 3장이 바뀌고 버튼은 비활성이 된다. (F5)
8. 후보 카드 하나를 누른다. "OO으로 확정할까요?"가 뜨고 "확정"을 누른다. (F6)
9. 화면이 "오늘 점심: OO"으로 바뀌고 도장 5칸 중 2칸이 찍힌 "익숙"과 "레벨 업! 이제 익숙입니다"가 보인다. 첫 방문이라 Lv1에서 Lv2로 오른 것이다. "다음 룰렛은 17:00에 열립니다"가 함께 보인다.
10. 하단 탭 "기록"으로 간다. "2026년 9월 4일 점심, 회사", 식당 이름, 도장 2칸이 찍힌 "익숙"이 보인다. (S4, F8)

## 화면 상태 전이 (S2 홈)

해피케이스에서 홈 화면이 거치는 상태다. 상태 정의는 [05-rules.md](05-rules.md) 세션 상태 표를 따른다.

```mermaid
stateDiagram-v2
    [*] --> idle: 슬롯 안 · 세션 없음
    idle --> open: 돌리기 (F4)
    open --> open: 다시 돌리기 1회 (F5)
    open --> confirmed: 확정 (F6)
    confirmed --> [*]: 다음 슬롯까지 잠금
```

## 문서와 Figma 연결 규칙

- FigJam의 각 노드 제목은 이 문서의 번호(S1, F4 등)로 시작한다. 번호로 문서를 찾는다.
- FigJam에서 흐름을 고치고 싶으면 이 파일의 Mermaid를 먼저 고치고 다시 렌더한다. FigJam은 결과물이다.
- 화면 디자인이 생기면(백로그 Q2) FigJam의 S 노드에서 디자인 파일의 프레임으로 링크를 건다.

## 렌더 방법

Figma MCP가 연결돼 있으면 `generate_diagram`에 위 Mermaid를 그대로 넘기고 `fileKey`에 `TYKrI6JL3kwlVwbXDZyTXL`을 주면 같은 보드에 새 다이어그램이 추가된다. 노드 텍스트는 전부 따옴표로 감싼다. 화살표 라벨이 길면 `<br/>`로 두 줄로 나눠야 화살표가 가려지지 않는다. 이전 다이어그램은 FigJam에서 직접 지운다.

MCP 없이 SVG로 가져오려면:

```
npx --yes @mermaid-js/mermaid-cli -i docs/superpowers/specs/2026-09-04-lunch-roulette/14-userflow-happy-case.md -o docs/figma/userflow-happy-case.svg
```

- 결과는 `docs/figma/` 아래에 SVG로 저장한다. 다이어그램이 두 개라 파일이 두 개(`-1.svg`, `-2.svg`)로 나온다.
- FigJam에서 파일 → 가져오기(또는 드래그 앤 드롭)로 SVG를 넣는다. 편집 가능한 도형이 필요하면 FigJam의 Mermaid 가져오기 플러그인에 위 코드 블록을 붙여 넣는다.
